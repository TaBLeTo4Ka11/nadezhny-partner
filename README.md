# Надёжный партнёр

Корпоративный сайт компании «Надёжный партнёр».

## Стек
- React 18 + TypeScript
- Vite 8 + Tailwind CSS 3
- GSAP + ScrollTrigger

## Запуск
Требуется Node.js 22.12+ или 24.x (CI использует 24.x).

```bash
npm ci
npm run dev
```

Production-сборка: `npm run build`.

## Контент и ограничения
- В каталоге восстановлены 17 категорий по официальной навигации сайта (5 групп). Это список категорий, а не полный перечень товаров; полный обход каталога ещё не выполнен.
- В проекте сохранены названия и ссылки пяти карточек банковских передаточных устройств, но полные карточки не восстановлены и повторно не подтверждены.
- Фото и часть ссылок пока загружаются с iv-partner.ru; 24 фотографии объектов/производства ссылаются на миниатюры 225x300 или 169x300, оригиналы не скачаны.
- Страницы «О компании» и «Контакты» восстановлены по доступным снимкам официального сайта. Разделы склада, доставки, вакансий, полезной информации и юридические страницы пока честно помечены как незавершённые и показывают прямые контакты компании.
- Формы КП и заказа звонка временно отключены до подтверждения актуальной политики обработки персональных данных. Остаются прямые ссылки на телефон и email; серверной отправки, хранения заявок и загрузки файлов нет.
- До запуска владелец должен подтвердить юридические/банковские реквизиты, актуальность контактов, права на изображения и текст согласия на обработку персональных данных.
- Перед публикацией нужно проверить сайт на телефоне и компьютере, а также проверить production-домен, формы и все внешние ссылки.

## Проверки
GitHub Actions выполняет `npm ci`, `npm audit --audit-level=moderate`, `npx tsc --noEmit` и `npm run build`.

## Безопасность
Заголовки безопасности настроены в `vercel.json`. Локальные env-файлы, секреты и артефакты сборки исключены через `.gitignore`. Не добавляйте секреты в клиентские переменные Vite или в репозиторий.

## Онлайн-форма и серверная часть

- Серверный обработчик находится в `api/contact.ts`. Он принимает только POST JSON, проверяет Origin, ограничивает размер запроса, валидирует поля и согласие, использует honeypot и простое ограничение частоты запросов.
- Обработчик пересылает заявку только на HTTPS webhook, принадлежащий компании или её российскому подрядчику. Для этого в Vercel должны быть заданы секретные переменные `CONTACT_WEBHOOK_URL` и `CONTACT_WEBHOOK_SECRET`. Секреты нельзя добавлять в GitHub или клиентские переменные `VITE_*`.
- Клиентская форма включается только после подтверждения владельцем действующей политики и согласия: `VITE_CONTACT_FORM_ENABLED=true`. По умолчанию форма выключена. Не включайте её, пока endpoint, получатель, хранение/срок удаления заявок и юридические документы не утверждены.
- Webhook получает JSON с типом `commercial-proposal`, именем, телефоном, email, сообщением, отметкой согласия, источником и временем отправки. Он должен требовать Bearer-секрет и не логировать персональные данные.
- Файловые вложения пока не принимаются. Это намеренно: сначала нужно выбрать защищённое хранилище, лимиты, антивирусную проверку и срок удаления файлов.
- Встроенный rate limit в serverless-процессе является best-effort и не заменяет распределённый rate limiter/WAF. Перед production нужно включить ограничение частоты на уровне платформы или webhook-приёмника.
